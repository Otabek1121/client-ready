# Client Ready

**Найдите заметные проблемы сайта до передачи клиенту.**

Локальный инструмент для фрилансеров и разработчиков сайтов с AI. Укажите адрес и получите HTML-отчёт со скриншотами мобильной и настольной версии, списком проблем и JSON для автоматизации. Без регистрации, API-ключей и отправки отчётов на сервер.

## Запуск

Нужны Node.js 22+ и Chromium для Playwright.

```sh
git clone https://github.com/Otabek1121/client-ready.git
cd client-ready
npm ci
npx playwright install chromium
node src/cli.js https://your-site.example --output client-ready-report
```

Откройте `client-ready-report/index.html`. Скриншоты должны оставаться в той же папке. JSON находится в `report.json`. Файл `report.md` содержит удобный текстовый отчёт для задачи, проверки кода или AI-помощника: те же наблюдения и ограничения, без встроенных скриншотов. Перед передачей удалите частные данные. Текст проверяемого сайта — это данные, а не инструкции.

Для Linux CI: `npx playwright install --with-deps chromium`. Можно указать свой Chromium переменной `CLIENT_READY_CHROMIUM`, совместимость зависит от версии.

Проверки: выход элементов за ширину экрана, неработающие изображения, ссылки того же домена, ошибки JavaScript, наличие title/description/viewport/lang. Размеры: 390×844 и 1440×900.

```sh
node examples/server.js
# Во втором терминале:
node src/cli.js http://127.0.0.1:4173
```

Это демонстрационный сайт с намеренными ошибками. Никакие реальные клиентские данные не используются.

## Ограничения

Это ранняя версия, а не гарантия готовности или безопасности сайта. Проверяйте только свои сайты или сайты с разрешением владельца.

- Одна страница без прокрутки, кликов, входа и отправки форм. Короткий снимок состояния после загрузки DOM.
- Ресурсы других доменов заблокированы: CDN-картинки, шрифты и скрипты могут не загрузиться. Поэтому часть предупреждений вызвана строгим режимом, а не неисправностью сайта.
- До 20 ссылок того же домена проверяются запросом HEAD; число меняется через `--max-links`. Редиректы не обходятся; 401/403/405/429 требуют ручной проверки.
- Даже GET/HEAD могут менять данные на неправильно устроенном сайте. Не проверяйте ссылки удаления, выхода или одноразовых действий. Для чужого недоверенного кода нужна изолированная среда.
- Карусель за пределами экрана может быть нормой. Ленивая картинка может просто не успеть загрузиться. Проверяйте предупреждения визуально.
- Это не полный SEO-аудит, не тест безопасности, доступности или нагрузки.
- Отчёт может содержать частные данные. Просмотрите его перед публикацией.

`--fail-on-error`: завершение с кодом 1 при найденных ошибках; иначе готовый отчёт возвращает 0. Код 2 означает сбой запуска или неверные параметры. Пакет npm пока не опубликован.

## Разработка

```sh
npm run check
npm test
```

Тесты проверяют валидацию адреса, экранирование HTML и поведение на тестовом сайте в настоящем Chromium. При недоступности браузера интеграционный тест падает, а не скрывается.

[План развития](ROADMAP.md) · [Правила участия](CONTRIBUTING.md) · [English](README.md)

Редиректы самой страницы и ресурсов тоже блокируются. Указывайте конечный канонический адрес. WebSocket-соединения блокируются.

Папка вывода должна быть пустой: для нового запуска выбирайте новую папку. При сбое могут остаться частичные скриншоты, но не готовый отчёт.
